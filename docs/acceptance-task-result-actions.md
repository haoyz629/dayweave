# 两状态结果与独立后续任务

本说明以最终确认的预览及新增的优先级、标签继承要求为准，替代此前在结果浮窗内选择继续安排／暂不安排／不再做的方案。

## 正式行为

- 任务结果只提供“完成／未完成”。移除部分完成、原因字段和浮窗内后续排程，未完成仅填写可选备注。
- 完成直接结束任务并将剩余量设为 0，不再复核；保留既有短时撤销与历史保护。
- 保存未完成只记录结果、执行备注和时间戳，不改任务状态、日期、剩余量或未执行安排，不自动创建新任务。
- 未完成保存后的 Toast 提供“创建后续任务”；任务详情页也有持久入口。已有未删除的后续任务时改为“查看后续任务”。已存在的关联草稿继续复用，不覆盖用户编辑。
- 后续任务草稿首次带入来源任务的标题、优先级、标签；任务备注和执行备注均不复制。日期默认中国标准时间的下一天，时间默认 09:00–10:00，均可编辑，且不参与关联匹配。
- 只有确认新建后，才产生新任务、日程及正式关联。创建失败保留草稿和输入。关联草稿只能创建独立普通任务，不能切换为重复事项。
- 新任务显示“来源任务”，原任务显示“后续任务”，按任务 ID 双向追溯，不依赖标题、备注或安排日期。跳转沿用草稿保存及未保存修改保护。
- 来源任务被移入回收站、完成、改名或改期，不会自动改变后续任务；来源永久删除时保留来源标题快照，不再提供失效跳转。
- 重复事项仍仅按规则展示，不增加完成勾选、结果记录或复核。
- 最近 7 天的历史首次补录仍只记录过去结果，不改变当前任务和安排。旧详细记录、部分完成和旧后续处理历史保持可读，兼容后端接口保留。

## 数据与事务

- v24 新增 `task_draft_origins` 和 `task_origins` 保存草稿来源与正式任务来源；来源外键采用 `ON DELETE SET NULL` 并保留不可编辑的标题快照。
- `prepare_task_followup` 原子地查找已有任务／草稿，或仅创建关联草稿；不修改来源任务。普通创建输入不能伪造来源。
- 确认任务与创建正式来源关系同一事务提交，防止重复关联；失败全部回滚。相同确认重试保持幂等。
- 新的未完成提交使用不带旧下一步字段的记录模式；既有排程版本和最终历史事实保护继续生效。
- 优先级和标签只在首次生成草稿时继承，之后以用户的草稿编辑为准，不随来源任务后续修改而覆盖。
