# 采用非独占日程时间线与软工作时间偏好

> 2026-11-28 更新说明：本 ADR 确立的**非独占时间轴**原则（允许任务与定时重复事项在同一时段重叠并列排布，不将重叠视为冲突）在 v2 工作台中继续有效；下文关于固定日程、日计划草案、工作时间设置及 AI 提议的 v1 上下文已由 `0008-unified-mica-workbench-and-three-mode-scheduling.md` 取代。

> 后续规则：本 ADR 的非独占与软偏好继续有效；下文自动安排／计划生成的流程描述不再授权日期页提供生成或重新排程入口，现由 `0005-single-day-direct-scheduling.md` 的单日正式保存直接安排、日常加入／移除／调时立即保存可撤销取代。已有整批草案仍先编辑、再确认；执行、复盘与历史保护按 ADR-0005，不改变 AI 只提议的边界。保留原决策上下文，不代表新规则重新验收。

## Context

今序原先把执行块、阻塞型固定日程、工作时间、午休和任务间缓冲共同解释为一组“可用空档”：已经存在的时间块会占用时段，重叠默认被拒绝，工作时间外和午休也会成为保存日计划的硬限制。这套模型适合资源预订，却限制了个人日程的真实表达。用户可能希望在同一时间保留多个意图，例如会议期间等待下载、通勤时听课程，或把多个可选任务并列放在同一时段。

2026-09-03 用户确认时间线应表达“希望这些事情在该时段发生”，而不是保证每分钟只能存在一项工作的资源占用表；同时确认取消午休、任务间缓冲以及所有“占用 / 阻塞 / 不阻塞”概念，并采用附件所示的普通任务块、重复事项块和重叠分列方式。

## Decision

1. 日计划时间线采用非独占模型。任务执行块、日计划草案块、固定日程和有展示时间的重复事项都允许在任意相交时段同时存在；重叠不是错误，也不需要例外确认。
2. 删除用户可见的“占用时间”“阻塞日程”“仅提示”“不阻塞安排”等二元语义。固定日程仍是不可由 AI 擅自移动的事实，但不会排除同一时段的任务。
3. 工作日和每日工作时间仅是安排偏好与时间线视觉参照，不是创建、编辑、确认或自动安排的硬限制。自动安排可以优先选择工作时间，但不得因为处于工作时间外而拒绝保存或标记为“计划外”。
4. 取消午休设置、午休时间线区块、午休校验和任务间缓冲设置。历史数据库列可为兼容旧数据暂时保留，但不再参与候选时段、冲突判断、草案失效或保存校验。
5. 取消“空档容量”概念。已有固定日程、执行块、草案块或重复事项不会从候选时间中扣除。自动安排可以为了可读性优先错开事项，但重叠必须始终是合法结果，不能因为重叠进入“未安排”。
6. 任务的最早开始、截止边界、预计工作量和剩余工作量继续保持有效。已安排分钟只表示某个任务已有多少工作量被分配到执行块，用于避免同一任务跨日重复分配；它不表示某段钟表时间已被独占。
7. 未确认草案、用户确认、SQLite 事务、执行记录和最终复盘边界保持不变。非独占时间线不授权 AI 直接写库，也不把执行块完成等同于长期任务完成。

## Overlap layout

具体空间算法以 `../design-apple-inspired-timeline-lanes-2026-09-04.md` 为准。它采用 Apple 日历式阅读模型作为可观察参考，但不宣称复刻 Apple 未公开的内部实现。

- 两个区间仅在 `start < other.end && end > other.start` 时视为重叠；前一项结束时刻等于后一项开始时刻不算重叠。
- 起止时间完全相同的事项横向等分可用宽度。四个 `15:00 - 16:00` 事项应呈现为四个等宽、同高且互不遮挡的块。
- 起止时间不同但存在交集的事项组成同一耦合组。每个事项保持真实纵向起止位置，并获得稳定基础列；短事项结束后，后续事项可以复用空出的列。
- 同一耦合组只在局部达到较高并发时，没有碰撞的事项可以从基础列向右扩展到连续空列；不得向左移动，也不得绘制中途变宽的 L 形卡片。
- 同起点事项按结束时间降序排列，使较长事项成为稳定左侧锚点；完全同起止事项再用稳定对象键打破平局。刷新、重新读取 SQLite 或输入数组换序后不得随机换列。
- 包含关系、部分交叠和链式交叠都必须计算完整耦合组，不能只比较相邻数组元素，也不能让长事项成为遮住其他内容的不可读背景。
- 时间包含只表示区间关系：被包含事项应与长事项并列显示，不得作为子卡片嵌入长事项。
- 视觉最小高度可以提高短事项的可读性，分列计算必须同时考虑该视觉占位；由此产生的视觉分列不得被解释成真实时间冲突。
- 同一耦合组内排序必须稳定，至少按实际开始、实际结束和稳定对象标识打破平局；重新读取 SQLite 后不得随机换列。
- 多列变窄时依次保留对象标识、标题和时间；说明、预计时长和结果细节进入统一悬浮与键盘聚焦说明。不得因列数增加而让勾选框或重复标识消失。

## Timeline block design

### 普通任务执行块

- 使用紧凑矩形、轻圆角、低对比度纸面和左侧细状态线；不照搬参考图的大面积高饱和深蓝。
- 首行依次为圆形勾选框和任务标题。勾选框固定在标题左上方、标题之前；不能垂直居中到整张卡片左侧，也不能在窄列中被隐藏。
- 第二行使用时钟图标和统一的 `起 - 止` 时间范围。状态色继续表达计划、完成、部分完成、阻塞、取消和未开始，并配合文字或可访问名称。
- 勾选只记录该执行块“本次完成”，不完成长期任务。最终复盘前允许取消勾选并撤销本次轻量执行记录；最终复盘后勾选锁定并提供原因说明。
- 点击任务块与点击勾选框是两个独立操作；勾选框以外的整个任务块打开执行记录/详情，勾选框只改变允许改变的本次执行状态。详情浮层贴近所选任务块并自动避让边缘，完整任务编辑仍由任务页承载。

### 日计划草案块

- 与普通执行块共享左侧细状态线、标题和时间层级，但不显示执行完成勾选框。
- 通过边框、纸面和“草案”文字清楚区分未确认状态；点击后可以调整时间，确认前不表达已经写入正式日计划。

### 重复事项块

- 重复事项继续使用独立规则和按日发生记录，不批量生成普通任务或执行块。
- 卡片密度、左侧细标识线、标题和 `起 - 止` 时间层级与普通任务块协调；右上角使用刷新/重复图标作为对象标识，不显示普通任务勾选框。
- 有展示时间的重复事项与其他所有时间线事项共同参与重叠分列，不再使用独立半宽轨道，也不再显示“不阻塞”说明。
- 重复事项默认不因点击打开详情弹窗；完整标题、时间、类型和当日复盘结果通过同一应用内悬浮卡覆盖鼠标悬停与键盘聚焦。
- 无展示时间的重复事项继续位于时间线顶部的重复事项区域。

### 固定日程与非工作时间

- 固定日程保留暖灰纸面和日历对象语义，但不显示“阻塞 / 仅提示”状态，也不排除同一时段任务。
- 非工作日和工作时间外区域位于小时网格底层，使用极浅中性底色或稀疏纹理；不使用事件式边框、圆角卡片、大段标签或独立焦点目标。
- 工作时间起止可在时间轴边缘提供克制标签，并通过可访问描述说明“工作时间仅为安排偏好，仍可在其他时间安排”。
- 当前时间红线位于背景与所有事项之上，不被非工作时间底色或重叠卡片遮住。

## Language

用户界面不用“排程”作为通用词，也不把所有场景机械替换为“日程”：

| 旧词 | 新词 |
|---|---|
| 排程 | 安排 |
| 已排程 | 已安排 |
| 可排程任务 | 可安排任务 |
| 排程规则 | 日计划偏好 |
| 排程草案 | 日计划草案 |
| 阻塞排程 / 占用时间 | 删除该概念 |
| 不阻塞排程 / 仅提示 | 删除该概念 |
| 固定日程 | 保持不变 |

内部枚举、旧数据库列和兼容接口可以暂时保留原英文名，但不得把已废弃语义继续暴露给用户或用于业务判断。本 ADR、迁移说明和验收清单可以在解释“删除什么”或验证旧数据兼容时引用旧词；历史快照也保持原文。除此之外，现行需求与用户界面不再使用这些词表达当前能力。

## Consequences

- `calendar_events.blocks_scheduling`、午休字段和缓冲字段需要兼容读取旧数据库，但新界面不再编辑它们，后端也不再依赖它们拒绝操作。
- 任务块与固定日程、已确认任务块或同一草案中的其他任务块重叠时必须允许原子写入；旧冲突测试应改为重叠成功且最终 SQLite 状态完整。
- 工作时间外和非工作日的任务块必须允许创建、编辑、确认和调整；工作时间只影响建议排序或默认落点。
- 计划生成不能再以“剩余空档分钟”判断整天容量；“未安排”原因不得使用时间不足、固定日程冲突、任务重叠、午休或工作时间外。
- 所有类别的时间线卡片必须使用同一重叠布局入口，避免普通任务、固定日程和重复事项各自计算后再次互相遮挡。
- 旧文档中“占用日历”“阻塞安排”“可用空档”“午休”“任务间缓冲”和“默认拒绝重叠”的条款由本 ADR 取代。

## Unchanged boundaries

- SQLite 仍是唯一事实来源。
- AI 写入仍遵循“生成草案 → 用户确认 → Rust/SQLite 事务”。
- 固定日程仍不可被 AI 擅自移动、缩短或删除。
- 任务最早开始与截止边界仍需校验。
- 完成执行块仍不等于完成长期任务；最终复盘事实不可被日间操作覆盖。
- 历史日期、执行记录和复盘记录不得因布局或词语变更被改写。
