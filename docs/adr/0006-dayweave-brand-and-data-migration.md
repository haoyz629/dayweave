# Dayweave 统一命名与旧数据迁移

## Decision

- 正式名称为“今序 · Dayweave”。仓库文件名、包名、Rust crate、工具、资源路径及 CSS 类统一使用 `dayweave`；常量和环境变量使用 `DAYWEAVE`。
- 当前应用标识为 `com.dayweave.desktop`，数据库为应用数据目录中的 `dayweave.sqlite3`，重复事项草稿键为 `dayweave.recurring_item_draft`，开机启动项名称为“今序 · Dayweave”。
- 旧名称仅允许出现在集中兼容模块、安装器兼容代码与对应测试夹具中，用于识别既有数据；不能通过抹掉这些字面量破坏升级。
- 不改写 Git 历史，不直接修改已安装应用的数据、注册表或旧构建产物；改名后的应用和安装器运行时才执行迁移。

## Upgrade behavior

1. 升级与首次启动前退出旧版，包括托盘。安装器检测到旧进程时要求关闭，不按进程名自动结束它。
2. 新数据库不存在时，启动逻辑从旧应用数据目录通过 SQLite 在线备份生成一致快照，包含已提交的 WAL 数据；快照完成后才发布为新数据库。不只复制数据库主文件。
3. 新 WebView 创建前复制旧应用本地目录中的 Local Storage，保留未导入草稿；不迁移浏览器缓存。新键已存在时以新值为准；旧键只有在新键保存成功后才移除。
4. 新数据库或新本地存储已存在时不覆盖。失败不发布不完整副本，旧数据保留，可修复原因后重试。应用不进行旧版与新版之间的双向同步。
5. 安装器复用已有当前用户安装位置，仅清理指向同一安装的旧快捷方式和卸载记录。开机启动迁移同时更新可执行文件路径与 Windows 的二进制批准状态，不能把已禁用状态重新启用。与其他安装路径关联的启动项不迁移、不删除。
6. 卸载只清理指向本次安装路径的当前启动项，不删除其他安装的数据。

保留的旧数据库仍可能含明文 API Key，和新数据库一样需要妥善保护；本次更名不会自动删除备份，也不新增加密承诺。

## Verification boundaries

- Rust 自动测试覆盖：新安装无副作用、包含 WAL 的数据库迁移、旧源保留、新数据不覆盖、失败后重试，以及 Local Storage 复制。
- Node 自动测试覆盖：草稿键迁移、当前值优先、写入失败保留源值及重试。
- 安装器钩子应单独做编译与隔离注册表测试；这些测试不等价于运行正式 Windows 安装包的完整升级验收。
- 标准验证入口见仓库 `README.md`。安装包只在用户明确要求或批准后构建，不以文档更新代替实际验收。
