# 今序前端需求文档

> 文档状态：冻结产品方案的前端实施说明（v1.0，2026-08-22）  
> 适用平台：Windows 桌面应用（Tauri v2 WebView）  
> 产品语言：简体中文  
> 固定时区：`Asia/Shanghai`  
> 上位依据：`product-decision-baseline-2026-08-21.md`、`../CONTEXT.md`、`../DESIGN.md`

本文件描述今序冻结方案与当前首发验收体验。2026-09-01 的实现结果见 `acceptance-2026-09-01.md`；若与冻结产品方案冲突，以冻结产品方案和后续设计决策为准。

## 1. 文档目标

本文件用于让产品、设计、前端、后端和测试对以下内容形成一致理解：

- 谁会使用今序，以及他们在什么情境下使用。
- 四个主页面分别承担什么职责，页面内部由哪些模块组成。
- 页面之间、页面与 AI 助手之间如何流转。
- 正常、空、加载、失败、锁定、过期和提交成功时界面应该怎样表现。
- 哪些状态只是前端草稿，哪些状态必须等待 SQLite 事务提交后才能显示为事实。

本文件不规定具体组件库、CSS 实现方式或后端表结构；字段含义和写入边界以领域文档与实施规格为准。

## 2. 目标用户

### 2.1 核心用户

今序面向需要把较多待办转化为现实日程的个人用户，典型特征包括：

- 每天任务较多，但可用时间受会议、休息和临时安排限制。
- 需要 AI 帮助整理任务或安排顺序，但不接受 AI 未经确认直接修改数据。
- 会持续数天或数周推进长期任务，需要区分“完成今天的执行块”和“完成整个任务”。
- 重视本地数据、历史真实性和明确的操作反馈。
- 以 Windows 桌面端为主要工作环境，既使用鼠标，也依赖键盘提高效率。

### 2.2 使用时的心理状态

- **早晨规划时**：希望快速知道今天能做什么，不想先整理复杂表格。
- **白天执行时**：注意力集中在当前时间段，需要低干扰地查看和调整计划。
- **临时记录时**：只想先保留想法，不一定已经知道日期、时刻和工作量。
- **晚间复盘时**：需要诚实记录事实，不希望系统替自己判断完成或自动延期。
- **使用 AI 时**：愿意对话补充信息，但必须清楚看见 AI 正在做什么、影响哪些对象，以及何时仍未写入正式数据。

## 3. 核心使用场景

### 3.1 早间生成今日计划

1. 用户收到 Windows 通知，或进入应用后看见“今日计划尚未生成”。
2. 用户主动点击“生成今日计划”，此时才调用 AI。
3. 若昨日仍有待复盘内容，先跳转复盘并完成必要记录。
4. AI 结合固定日程、可用时间和已确认任务生成日计划草案。
5. 用户检查、拖拽、锁定、删除或调整草案中的执行块。
6. 用户确认后，页面等待事务完成并重新读取数据，再显示已确认时间线。

### 3.2 从月历理解某一天

1. 今日页默认显示当前月份并选中今天。
2. 用户从任务标记、节假日和日期详情理解当天情况。
3. 用户切换日期后，详情区同步展示当天固定日程、执行块和截止任务。
4. 用户可从详情区新建任务、新建固定日程或安排选中日期。

### 3.3 手动创建任务

1. 用户从任务页、今日页日期详情或命令面板发起“新建任务”。
2. 系统创建一条手动任务草案，并打开统一任务表单。
3. 草案在停止输入约 500ms 后自动保存，但仍不是正式任务。
4. 有日期时确认进入待办；无日期时主操作为“确认并放入 Inbox”。
5. 提交成功后重新读取 SQLite，并提供 10 秒事务撤销入口。

### 3.4 通过 AI 创建或调整任务

1. 用户展开右下角 AI 助手，选择“创建任务”或“调整任务”。
2. AI 通过文字对话澄清缺失信息，并流式显示回复。
3. 完整结构化结果通过本地校验后，一次更新到任务草案。
4. 页面跳转到任务页“草案”筛选并选中对应草案，AI 浮窗保持展开。
5. 用户逐条检查和确认，不提供“全部创建”。

### 3.5 白天调整剩余计划

用户新增任务后，已确认时间线不会自动变化。只有用户主动点击“加入剩余日程”或“安排当天”，才针对剩余空档生成局部草案；确认后才更新日历。

### 3.6 晚间复盘

1. 用户收到 Windows 通知并主动进入复盘页。
2. 页面通过固定表单逐项记录完成、部分完成、未开始、取消或阻塞。
3. 用户核对实际耗时，可补充延期原因、备注和剩余工作量。
4. 提交后保留原计划、实际结果和工作量变化。
5. 完成执行块不会自动完成长期任务；只有用户明确确认，任务状态才变为完成。

| 设置 | 左侧“设置” | 配置 AI、时间、通知和界面 | 是 |
| 首次运行引导 | 首次启动 | 完成最低必要设置并进入应用 | 否 |

### 4.3 关键路由规则

| 触发动作 | 目标界面 | 必须保留的上下文 |
|---|---|---|
| AI 创建/调整任务完成 | 任务页“草案”筛选并选中对应草案 | AI 浮窗保持展开、当前对话不变 |
| AI 安排计划完成 | 今日页目标日期的“日计划” | 目标日期、草案版本、当前对话 |
| 月历“新建任务” | 任务页手动草案 | 预填选中日期 |
| 月历“新建日程” | 选中日期的固定日程表单 | 预填选中日期 |
| 晨间通知点击 | 今日页日计划；若有待复盘则先到复盘页 | 当天日期、待复盘原因 |
| 草案“查看来源对话” | 展开 AI 浮窗并切换对应对话 | 当前草案仍保持选中 |
| AI 浮窗切换对话 | 留在当前页面 | 不自动跳转；仅更新浮窗内容 |

## 5. 应用壳与全局模块

### 5.1 左侧主导航

模块结构：

- 品牌标记“今序”。
- 今日、任务、复盘、设置四个入口。
- 与下一步行动有关的少量计数，例如草案数、Inbox 待整理数或待复盘数。
- 底部显示今日计划的简要进度；无计划时使用说明文字，不显示虚假的 0% 成功状态。

交互要求：

- 当前页面同时用背景、字重和 `aria-current` 表达，不能只靠颜色。
- 导航切换不关闭 AI 浮窗，也不丢失当前对话。
- 页面存在未保存表单时切换导航，应保留已自动保存草案；正式任务未提交修改则提示保存、放弃或留在当前页。
- 桌面端侧栏宽度可调并持久化；键盘也能调整，双击分隔条恢复默认宽度。

### 5.2 全局顶栏

- 只呈现当前操作需要的日期或对象上下文，不重复左侧导航已经表达的页面名称。
- 明暗模式切换。
- 命令面板入口。
- 必要时显示通知或数据异常入口，不堆叠低价值图标。

### 5.3 全局反馈

- **即时 Toast**：用于自动保存结果、非阻断错误、AI 锁定说明等；需简短且可被辅助技术读取。
- **页面内状态区**：用于读取失败、提交失败、冲突、草案过期等需要用户处理的状态，不应只显示 Toast。
- **10 秒撤销条**：用于已确认的创建、修改和排程。显示对象和剩余时间；撤销失败时保留说明和查看详情入口。
- **确认对话框**：用于软删除、永久删除、重复任务作用范围和会覆盖时间块的冲突选择。

成功文案只能在事务提交成功且重新读取 SQLite 后出现。按钮点击、模型回复或前端乐观状态都不能单独触发“已完成”“已创建”等事实文案。

## 6. 今日页

### 6.1 页面目标

让用户从日期出发理解任务与现实时间，完成“看日期—看当天—安排当天—执行当天”的闭环。默认子视图为月历。

### 6.2 页面模块结构

1. **页面标题区**
   - 当前年月。
   - 回到今天。
   - 上一月、下一月。
   - “月历 / 日计划”子视图切换。
2. **提醒区**
   - 今日计划尚未生成。
   - 昨日存在待复盘内容。
   - 节假日数据覆盖年份或数据异常。
3. **月历网格**
   - 星期标题。
   - 日期单元格按当月实际跨越的自然周动态显示 4–6 行。
   - 只补齐当月首日和末日所在周；不得为维持固定高度继续展示下一月的额外整周。
   - 今天、选中日期、非当前月日期。
   - 节日、调休、农历节日、节气。
   - 任务圆点与数量。
4. **选中日期详情**
   - 日期标题与节日信息。
   - 固定日程。
   - 已确认执行块。
   - 当天截止但未排程的任务。
   - 新建任务、新建日程、安排当天。
5. **日计划视图**
   - 时间轴。
   - 固定日程。
   - 日计划草案或已确认执行块。
   - 未排入今日及原因。
   - 计划进度与实际耗时摘要。

### 6.3 月历交互

- 默认显示当前月并选中今天；重新进入今日页时保留用户当前选中日期，应用重启后默认回到今天。
- 单击日期更新详情区；键盘方向键移动日期焦点，`Enter` 或 `Space` 选中。
- 切换月份时保持明确的月份标题和焦点位置；只要当前浏览月份不是本月，或选中日期不是今天，就显示“回到今天”。点击后同时切回当前月并选中今天。
- 今天与选中日期必须使用不同视觉语义，即使二者是同一天也能同时表达。
- 有未完成任务的日期显示蓝色圆点和数量；只有已完成任务时使用淡化圆点。颜色之外保留可访问名称。
- 无日期 Inbox 任务不进入月历。
- 已排程任务按执行日归属；未排程但有截止日期的任务按截止日归属。

### 6.4 选中日期详情交互

- 选中今天时标题写“今日安排”；其他日期显示完整日期与星期。
- “新建任务”打开手动草案并预填所选日期，用户仍可清除日期。
- “新建日程”打开固定日程表单；保存前不影响排程。
- “安排当天”展开 AI 助手并绑定所选日期；AI 浮窗从页面上方覆盖，但不能永久挡住详情区主操作。
- 点击任务或执行块进入对应详情；点击固定日程进入编辑表单。

### 6.5 日计划交互

- 草案和已确认计划必须在标题、背景和操作文案上明显区分。
- 用户可以拖拽、缩放、删除或锁定草案执行块；键盘用户必须有等价的时间编辑方式。
- 与固定日程冲突时禁止保存，并指出冲突对象和可用空档。
- 与其他任务块冲突时默认禁止；用户可以明确选择替换、移动原任务或保留重叠。
- 超出可用时间允许手动保存，但标注“计划外”。
- 未排入任务必须显示具体原因，例如时间不足、约束冲突或缺少工作量。
- 确认前可以持久化日计划草案，但不能把草案展示为已占用日历。
- 完成执行块后显示“执行块已完成”，不得自动把长期任务显示为完成。

### 6.6 今日页状态

| 状态 | 界面要求 | 主要操作 |
|---|---|---|
| 首次加载 | 保留月历和详情骨架，避免整页空白；禁止使用只有旋转图标的全屏遮罩 | 等待、取消不了的读取不显示假按钮 |
| 无任务、无日程 | 月历仍完整展示；详情写“这一天还没有安排” | 新建任务、新建日程、安排当天 |
| 有任务但无计划 | 展示截止任务和提示“尚未安排到具体时间” | 生成或手动安排 |
| 今日计划未生成 | 页面内提醒，不自动调用 AI | 生成今日计划 |
| 昨日待复盘 | 明确说明为什么暂不能生成完整计划 | 去复盘 |
| AI 生成中 | 只锁定目标日期草案；其他日期仍可浏览 | 停止分析 |
| 草案过期 | 保留旧草案内容并解释哪些数据已变化 | 重新生成、放弃草案 |
| 读取失败 | 月历结构不坍塌，错误就近出现 | 重试 |
| 提交失败 | 保留用户调整过的草案，不回退成空白 | 重试、查看冲突 |
| 节假日数据缺失 | 日历和任务仍可用，显示覆盖异常 | 查看说明 |

## 7. 任务页

### 7.1 页面目标

统一承接手动任务、AI 任务草案、Inbox 任务和正式任务生命周期，让用户能快速扫读列表，并在同一工作区完成编辑与确认。

### 7.2 页面模块结构

1. **标题与搜索区**
   - 页面标题。
   - 任务搜索。
   - 新建任务。
2. **筛选区**
   - 草案、Inbox、待办、已排程、已完成、已取消、回收站。
   - 标签筛选。
   - 各筛选的必要计数。
3. **任务账本列表**
   - 状态文字与辅助状态点。
   - 标题和摘要。
   - 优先级、工作量、日期。
   - “AI 生成 / 手动创建”来源。
   - 草案缺失字段和校验状态。
4. **详情检查器**
   - 任务草案表单、正式任务表单或回收站详情。
   - 修改草案的旧值/建议值差异。
   - 变更历史和关联执行块入口。
   - 与当前状态对应的底部操作层。

### 7.3 账本布局

- 桌面端默认约 34/66 双栏：左侧列表，右侧详情。
- 状态筛选采用可横向滚动的胶囊控件；当前筛选使用靛蓝底和白字。
- 任务行使用无阴影白色账页、浅边框和轻圆角；用 1px 优先级色线、优先级文字、标题、最多两行说明和日期/工作量元数据建立扫读层级。
- 选中任务使用淡靛蓝纸面和更清晰边框，不依靠阴影或单一颜色表达。
- 列表与详情之间可通过鼠标和键盘调整宽度，并持久保存。
- 双击分隔条恢复默认比例。
- 空间不足时改为上下排列；选中列表项后详情应自动进入可见区域。
- 列表滚动位置和当前筛选在返回页面时保留。

### 7.4 筛选与搜索

- 用户首次进入任务页默认显示“待办”，随后恢复上次使用的筛选；当 AI 新产生草案时必须切换到“草案”并选中结果。
- 筛选使用明确文字、计数和 `aria-pressed`，不能只用下划线颜色。
- 搜索覆盖正式任务和草案，但回收站结果只在回收站筛选中出现。
- 无搜索结果要保留搜索词，并提供清除搜索；不能误导为没有任何任务。

### 7.5 统一任务草案表单

建议按以下组组织字段，避免一次展示过长表单：

1. **基本信息**：标题、备注、优先级、标签。
2. **日期约束**：最早开始日期、可选时刻、截止日期、可选时刻。
3. **工作量**：总工作量、剩余工作量、单位换算、是否允许拆分。
4. **重复**：每天、工作日、每周指定星期、每月指定日期、可选结束日期。
5. **来源与依据**：任务来源、来源对话、字段级状态。

交互要求：

- 只有标题是创建必填项；日期与具体时刻分开输入。
- 用户输入“下周五”时，不能由界面默认补成 18:00 或 23:59。
- 草案停止输入约 500ms 后自动保存，显示轻量“已保存草案”；自动保存不显示“任务已创建”。
- 字段级状态为“来自描述”“AI 整理”“需确认”“手动修改”。手动修改优先级最高。
- 无日期草案主按钮写“确认并放入 Inbox”；有日期草案写“确认创建任务”。
- 一次存在多条草案时逐条确认或放弃，不出现批量创建按钮。
- 修改草案显示原值和建议值，用户逐项理解后再确认。
- 正式任务来源只显示“AI 生成”或“手动创建”；后续修改不改变首次来源。

### 7.6 正式任务详情

- 表单与 SQLite 一致时不显示悬浮保存操作。
- 用户修改字段后，底部出现“有未保存的更改”操作层，提供保存和放弃。
- 状态操作只展示当前领域状态允许的选项。
- 完成长期任务必须是独立且明确的用户操作，不与完成执行块共用按钮。
- 重复任务修改时只提供“仅修改本次”和“修改本次及以后”。
- 软删除进入回收站；永久删除只在回收站内提供，并需要独立确认。

### 7.7 任务页状态

| 状态 | 列表表现 | 详情表现 |
|---|---|---|
| 首次加载 | 使用与真实行尺寸一致的骨架，保留筛选和搜索 | 显示检查器骨架 |
| 当前筛选为空 | 说明该筛选含义，不使用庆祝式大插画 | 提供与筛选相关的下一步 |
| 草案为空 | “还没有待确认草案” | 新建任务、打开 AI 助手 |
| Inbox 为空 | “Inbox 已整理完” | 新建无日期任务 |
| 搜索无结果 | 显示搜索词和当前筛选 | 清除搜索、切换筛选 |
| 自动保存中 | 当前草案行显示轻量进度 | 字段继续可编辑，不阻塞整页 |
| 自动保存失败 | 草案行显示未保存标识 | 保留输入，提供重试 |
| AI 锁定 | 仅目标草案或任务显示锁定状态 | 控件只读并说明先停止分析 |
| 版本冲突 | 保留用户内容并标识数据已更新 | 重新读取、查看差异、另存草案 |
| 提交中 | 仅相关操作禁用，按钮写“正在创建/保存” | 防止重复点击 |
| 提交失败 | 列表不假装新增成功 | 保留表单和错误恢复入口 |
| 回收站为空 | 说明默认保留 30 天 | 返回其他筛选 |

## 8. 复盘页

### 8.1 页面目标

以固定表单记录事实，处理当日和待补复盘内容；不使用 AI 对话代替用户填写。

### 8.2 页面模块结构

1. **日期与摘要**：复盘日期、计划总量、已记录数量、待处理数量。
2. **待复盘提醒**：跨日未处理内容及其阻断今日计划的原因。
3. **复盘条目列表**：执行块或任务实例、原计划时间、原预计时长。
4. **条目表单**：结果、实际耗时、延期原因、备注、剩余工作量。
5. **提交与历史**：保存本次复盘、查看历史日期。

### 8.3 表单交互

- 每项结果为：完成、部分完成、未开始、取消、阻塞。
- 实际耗时默认带入计划时长，但必须允许修改，并明确这是建议值。
- 延期原因和备注可选；剩余工作量可重新估算。
- “完成执行块”与“完成整个任务”使用不同文案和不同确认动作。
- 用户保存复盘后保留原计划值，不把实际值覆盖成新的原计划。
- 未完成的长期任务继续成为未来计划候选。

### 8.4 复盘页状态

- **当天无执行块**：显示“今天没有需要复盘的执行块”，仍可查看历史。
- **有待补复盘**：置顶并优先处理，明确今日计划受限原因。
- **部分已填写**：保留本地表单内容，显示已完成数量。
- **提交中**：只锁定本次提交条目，其他历史仍可查看。
- **提交失败**：保留全部输入，逐项标出错误并提供重试。
- **历史读取失败**：当前表单不受影响，历史区域独立重试。

## 9. 设置页

### 9.1 页面目标

集中管理会影响 AI、排程、提醒和阅读体验的规则，避免把可用性设置分散在日历页。

### 9.2 页面模块结构

1. **AI 连接**
   - 连接器类型：Chat Completions 兼容 / Responses API 兼容。
   - Base URL、模型名、API Key。
   - 测试连接。
   - 最小上下文和明文存储风险说明。
2. **工作时间与排程**
   - 工作日。
   - 每日开始、结束。
   - 午休。
   - 任务间缓冲。
   - 每个工作日换算时长。
3. **提醒**
   - 晨间计划时间。
   - 晚间复盘时间。
   - 任务块开始前提醒。
   - Windows 通知总开关。
4. **外观**
   - 默认、GitHub、Codex 三套主题。
   - 明暗模式。
   - 中文验证字体。
   - 小、标准、大、特大字号。
5. **应用行为**
   - 开机启动。
   - 关闭窗口时最小化到托盘。
   - 全局快捷键。
6. **数据与隐私**
   - 数据库位置和风险说明。
   - 审计记录查看与清理。
   - 回收站保留说明。
   - 后续才提供的导出、备份能力不得显示为可用。

### 9.3 设置交互

- 设置按模块独立保存，避免修改一个字段后必须提交整页。
- API Key 默认掩码；不提供无意间复制或日志回显的路径。
- “测试连接”使用独立测试状态，不携带真实任务、日历或 Inbox 内容。
- 时间规则存在矛盾时就近校验，例如结束早于开始、午休越界、未选择工作日。
- 更换主题或字号可以即时预览，但持久化失败时恢复数据库中的值并说明原因。
- 影响排程的设置变化要提示现有日计划草案可能过期，但不能静默重排。

### 9.4 设置页状态

- 未配置 AI：完整显示手动功能说明和配置入口，不把应用整体标为不可用。
- 测试连接中：只禁用连接配置区，允许使用其他设置。
- 连接成功：显示连接器与模型名，不显示 Key。
- 认证、网络、模型或输出不兼容：分别给出可执行错误，不统一写“连接失败”。
- 保存失败：保留输入并提供重试；敏感字段不得出现在错误详情。

## 10. 全局 AI 助手

### 10.1 形态与位置

- 宠物图标固定在应用窗口右下角，不是 Windows 桌面级窗口。
- 不支持拖动或缩放；浮窗从图标上方展开。
- 用户展开后跨页面保持，只有主动点击收起才关闭面板。
- 浮窗约 380px 宽，高度不超过窗口的 72%，并保留安全边距。
- 打开时不能永久遮挡页面底部提交按钮；页面必须可滚动到被覆盖区域。

### 10.2 图标状态

| 状态 | 表现 | 说明 |
|---|---|---|
| 空闲 | 静态 | 不随机移动、不主动展开 |
| 分析中 | 轻微呼吸 | 尊重减少动态效果设置 |
| 待用户回答 | 橙色状态点并配可访问文字 | 表示需要补充信息 |
| 草案就绪 | 蓝色状态点和数量 | 表示有待确认草案 |
| 失败 | 红色状态点和文字说明 | 点击后定位错误消息 |

### 10.3 浮窗模块结构

1. **标题栏**：当前对话标题、对话切换、收起。
2. **对话切换器**：搜索、新建、今天/更早分组、归档入口。
3. **消息区**：用户消息、AI 回复、系统状态、查看关联草案。
4. **快捷操作**：创建任务、调整任务、安排计划。
5. **输入区**：纯文字输入、发送或停止分析。

不提供“查询日程”快捷操作，不支持图片、附件、语音或引用控件。

### 10.4 对话管理

- 支持新建、切换、搜索、自动命名、手动重命名、归档、恢复和永久删除。
- 切换器按“今天 / 更早”分组；当前对话有明确勾选状态。
- 归档只从默认列表隐藏，不影响关联草案；归档列表可以搜索和恢复。
- 永久删除对话需要独立确认；存在关联草案时先引导处理草案。
- 消息分页加载；加载更早消息时保持当前滚动位置。
- 切换对话不自动跳转页面；存在关联草案时显示“查看草案”。

### 10.5 分析、锁定和停止

- 对话文字允许流式出现，但不完整结构化结果不能更新草案。
- 分析绑定当前对话、目标对象和版本。
- 只锁定被分析影响的草案、任务或目标日期计划，其他页面和对象仍可操作。
- 用户尝试修改被锁对象时显示 Toast：“AI 正在分析，停止分析后可修改”。
- 分析时发送按钮变为暂停样式图标，但可访问名称和 Tooltip 必须写“停止分析”。
- 停止后保留已显示文字并标记“已停止生成”，不生成或更新结构化草案。
- 停止或过期运行的迟到结果永久作废，界面不得随后跳转或显示草案成功。

### 10.6 AI 与表单同步

- AI 回复可以单向更新关联任务草案表单。
- 用户直接修改表单不向对话追加消息。
- 手动修改字段不能被后续 AI 自动覆盖。
- AI 若需改变手动字段，必须由用户在对话中明确要求，并再次确认新值。

### 10.7 AI 助手状态

- **首次空对话**：显示三个快捷操作和一条简短能力边界，不显示伪造示例结果。
- **无 AI 配置**：保留对话历史，输入区说明需配置连接，并提供“前往设置”；手动任务功能继续可用。
- **消息加载中**：使用消息骨架，保持输入区可见。
- **流式中**：显示文本和停止按钮，不展示“草案已生成”。
- **等待回答**：问题和可选快捷回答就近出现，用户仍可自由输入文字。
- **结构校验失败**：保留自然语言回复，明确未更新草案并提供重试。
- **网络失败**：保留输入和对话，提供重试；不清空草案。
- **已停止**：保留部分文字和状态标记，不提供继续生成按钮，只能重新发送。
- **草案就绪**：显示草案数量和“查看草案”，并按规则路由到任务页或日计划。

## 11. 首次运行引导

首发采用最多三步、可跳过的引导：

1. 工作日、可用时段、午休和缓冲。
2. 晨间计划、晚间复盘和任务提醒时间。
3. AI 连接配置与测试。

交互要求：

- 每一步说明设置如何影响计划，不使用营销式长文。
- 用户可跳过 AI 配置并正常进入应用。
- 必填错误就近展示；返回上一步不丢失输入。
- 完成后进入今日月历；未配置的项目可以在设置中继续完成。

## 12. 命令面板

- 用于搜索任务、跳转页面、打开任务草案或固定日程表单、触发今日计划。
- 不能建立第二套 Inbox 捕捉模型，也不能绕过草案和确认流程。
- 最近使用和搜索结果分组显示；每项写明将发生的动作。
- 键盘上下移动、`Enter` 执行、`Esc` 关闭，焦点关闭后回到触发位置。
- 无结果时提供创建任务或清除搜索，不显示无关推荐。

## 13. 通用状态规范

### 13.1 加载状态

- 首次读取使用与最终布局接近的骨架，避免页面跳动。
- 局部读取只加载对应模块，不用全屏遮罩阻塞整个应用。
- 加载时间较短时避免闪烁；较长时显示正在读取的对象，例如“正在读取任务草案”。
- 已有旧数据时保留旧内容并显示刷新状态，不先清空页面。

### 13.2 空状态

每个空状态由三部分组成：发生了什么、为什么合理、下一步做什么。文案必须与当前筛选或日期有关。

- 不用超大插画占据工作区。
- 不把“搜索无结果”和“数据库没有数据”混为一种空状态。
- 不把“没有任务”统一表达成庆祝，因为用户也可能只是未完成配置或筛选错误。
- 主操作最多一个，次操作最多两个。

### 13.3 错误状态

- 错误就近出现在受影响模块，并保留用户输入。
- 区分读取失败、校验失败、版本冲突、事务失败、网络失败和 AI 输出无效。
- 错误文案包含恢复动作，不只显示错误代码。
- 可复制技术详情应默认折叠，并移除 API Key 和敏感上下文。
- 某模块失败时，其他不相关模块仍可使用。

### 13.4 提交状态

- 只禁用会造成重复提交的相关控件，不冻结整个应用。
- 按钮文字由动作变为“正在创建”“正在保存”“正在确认计划”等具体状态。
- 防止重复点击，但后端仍必须保证幂等。
- 成功后重新读取 SQLite；若读取失败，不得仅凭提交响应展示完整成功状态。

### 13.5 只读与锁定状态

- AI 锁定、回收站对象和过期草案使用不同视觉与文案。
- 禁用控件仍需可读，并就近解释为什么不可操作。
- 锁定不能只通过降低透明度表达；提供文字状态和停止分析入口。

### 13.6 过期与并发状态

- 草案或计划版本过期时保留当前内容，不静默覆盖。
- 显示变更来源和可选动作：重新读取、查看差异、重新生成或放弃。
- 用户手动字段优先；AI 迟到结果不触发页面跳转、Toast 成功或计数变化。

## 14. 视觉风格

### 14.1 创意方向

视觉北极星为“安静的任务账本”：长期使用时克制、可信、易扫读。界面重视数据事实和操作层级，不追求营销式冲击。

- 浅暖灰工作台、近白账本纸面、深墨文字。
- 靛蓝只用于当前选中、键盘焦点和确定性交互线索。
- 完成绿、取消棕、删除红只表达生命周期状态，并始终配合文字。
- 不使用大面积渐变、玻璃拟态、强阴影或每行一张悬浮卡片。
- Apple 日历只作为月历信息层级和清晰度参考，不复制品牌外观。

### 14.2 字体与层级

- 字体：Segoe UI Variable；中文回退 Microsoft YaHei UI、Noto Sans CJK SC。
- 页面标题约 31px，高字重；模块标题约 20px；正文和关键操作不低于 13px。
- 标签不以 9–10px 小字承载关键状态、错误或下一步操作。
- 同一页面最多使用必要的四级文字层级，避免所有模块都抢夺注意力。

### 14.3 形状、边界和深度

- 常规控件使用 8–10px 轻圆角，重点浮层最多 14px。
- 依靠纸面色阶、1px 浅边界和间距组织层级。
- 阴影只用于 AI 浮窗等必须脱离页面的对象。
- 普通按钮不使用全胶囊；胶囊只用于小型计数和进度。

### 14.4 动效

- 动效只解释状态变化，例如浮窗展开、列表插入、AI 分析呼吸和撤销倒计时。
- 常规过渡保持短促，不使用弹跳或随机宠物动作。
- 系统启用“减少动态效果”时关闭呼吸、位移和非必要动画。
- 数据状态变化必须由文字反馈支撑，不能只靠动画表达。

## 15. 响应式与窗口尺寸

- **宽窗口**：左侧导航 + 主工作区；任务页内部为可调双栏，今日页为月历 + 日期详情。
- **1180px 以下**：先收紧水平留白和详情宽度，不立即隐藏核心信息。
- **860px 以下**：隐藏桌面侧栏和拖拽柄；提供可访问的导航展开入口。月历详情移到网格下方，任务页改为上下结构。
- 表单在空间不足时切为单列；筛选可横向滚动。
- AI 浮窗受视口约束，始终保留安全边距；极窄窗口中占据可用宽度但仍可收起。
- Windows 125%、150%、200% 缩放下不得截断主操作、确认对话框或底部表单操作层。
- 桌面最小支持窗口尺寸应在实现前根据真实内容测定；小于可用下限时允许页面滚动，不压缩到不可操作。

## 16. 键盘与无障碍

- 所有主操作可由键盘到达并执行；焦点顺序符合视觉顺序。
- 焦点使用清晰靛蓝轮廓，不因鼠标样式而移除。
- 图标按钮必须有中文可访问名称和 Tooltip。
- 状态、优先级、错误和选中不能只依赖颜色。
- 月历使用合适的网格/日期语义；方向键移动焦点，月份切换后播报新月份。
- 分隔条使用 `role="separator"`、数值属性和方向键调节。
- Toast、自动保存和分析状态使用合适的 `aria-live`，避免反复打断屏幕阅读器。
- 模态框打开后焦点进入，关闭后回到触发控件；`Esc` 仅关闭可安全取消的浮层。
- 正文、状态和控件对比度满足 WCAG AA；危险操作不能只用红色区分。

## 17. 数据范围与性能考虑

前端至少按以下规模设计，不将少量演示数据当作真实上限：

- 月历：按当月首日偏移与天数动态显示 4–6 行，只补齐首尾边界周；单日可能有 0–20 条任务或日程，格内只显示摘要，详情区承接完整列表。
- 任务：可能存在数千条正式任务和数百条草案；列表需要分页或虚拟化，搜索输入不能导致明显阻塞。
- 对话：可能存在数百个对话和长消息历史；切换器和消息均分页加载。
- 复盘：单日可能有数十个执行块；长表单支持分段保存或稳定保留未提交输入。
- 状态计数应来自统一查询结果，不能由前端多个数组分别推算导致不一致。

## 18. 前端数据与事实边界

- SQLite 是唯一事实来源，React 状态只是数据库事实、未提交表单或可丢弃视图状态的投影。
- 手动任务草案和 AI 任务草案必须持久化，不能只存在组件内存。
- 页面切换和应用重启后，对话、草案、筛选偏好和可持久化布局设置按规则恢复。
- 所有写操作通过 Rust 命令；前端不能执行 SQL，也不能把模型输出直接转为正式任务或执行块。
- 事务成功后重新读取相关数据，再更新列表、计数、日历标记和成功文案。
- 读取、写入和 AI 分析使用独立状态，避免一个全局 `loading` 锁住整个应用。

## 19. 前端验收清单

### 19.1 信息架构

- [x] 主导航只有今日、任务、复盘、设置。
- [x] Inbox 只作为任务页筛选，月历只属于今日页。
- [x] 今日页默认显示日计划，并可切换完整月历。
- [x] 月历按当月实际跨越的自然周动态显示 4–6 行，不强行追加下一月的额外整周。
- [x] AI 助手是应用级右下角浮窗，切页后保持，用户手动收起。

### 19.2 任务与计划

- [x] 手动和 AI 创建共用任务草案表单，并显示正确来源。
- [x] 草案自动保存不被表达为正式任务创建成功。
- [x] 无日期草案确认进入 Inbox；有日期草案不自动占用日历。
- [x] 多草案逐条确认，没有“全部创建”。
- [x] 日期和时刻分开，界面不补造未提供的具体时刻。
- [x] 完成执行块不会自动完成长期任务。
- [x] 重复任务只提供“仅修改本次”和“修改本次及以后”。

### 19.3 AI 助手

- [x] 支持多对话、搜索、今天/更早分组、重命名、归档与恢复。
- [x] 仅有创建任务、调整任务、安排计划三个快捷操作。
- [x] 分析状态、模型回复和完整结构化结果的边界清楚。
- [x] 停止后已保存消息保留，迟到结构化结果不生效。
- [x] AI 修改只进入持久化草案，用户确认前不会覆盖正式任务或手动字段。

### 19.4 页面状态

- [x] 四个主页面和 AI 助手均具备加载、空、错误和恢复说明。
- [x] 搜索无结果与数据为空使用不同文案。
- [x] 提交失败保留用户输入；版本冲突不静默覆盖。
- [x] 成功反馈只在事务提交并重新读取 SQLite 后出现。
- [x] 创建、修改和排程成功后提供 10 秒事务撤销。

### 19.5 视觉与可访问性

- [x] 符合“安静的任务账本”视觉方向，不使用大面积渐变、玻璃拟态和卡片堆叠。
- [x] 状态不只靠颜色表达；关键文字不使用过小字号。
- [x] 主要操作具备鼠标、键盘、可访问名称和减少动态效果路径。
- [x] 1280×800 桌面窗口及窄窗口规则下，主操作不会被固定助手永久遮挡。
