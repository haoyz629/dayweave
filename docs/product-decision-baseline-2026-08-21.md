# 今序冻结产品方案（2026-08-21）

> 状态：已冻结，作为后续产品、架构、界面和测试任务的共同基线。文档或现有代码与本文件冲突时，以本文件为目标方向；若后续改变本文件中的边界，应同步修改 `CONTEXT.md`、`PRODUCT.md`、`DESIGN.md`、`frontend-requirements.md`、`jinxu-product-overview.md`、`ai-todolist-implementation-spec.md`、`README.md` 及相关 ADR。

> 2026-09-03 更新说明：本文件保留为历史冻结快照。涉及时间块独占、固定日程阻塞、可用空档、工作时间硬限制、午休、任务间缓冲、重叠冲突和“排程”用户文案的条款，已由 `adr/0003-adopt-non-exclusive-daily-timeline.md` 取代；其余边界继续有效。

## 1. 本次替代的旧方向

- 放弃首页内“输入框下方直接展示 AI 草案”以及固定左右对话/草案工作台。
- AI 助手不再属于今日页内容，而是应用内全局浮动能力。
- 今日页不再同时依赖独立 Inbox 与日历导航；日期和任务承接重新归位。

## 2. 导航与页面职责

左侧首发主入口为：

1. **今日**：默认月历，可切换日计划。
2. **任务**：草案、Inbox、待办、已排程、已完成、已取消和回收站。
3. **复盘**：当日固定表单与历史复盘。
4. **设置**：AI、工作时间、提醒、主题、快捷键与数据管理。

独立 Inbox 和日历入口移除：Inbox 成为任务页筛选；固定日程在今日页选中日期详情中维护，可用性规则移入设置。

## 3. 今日页

### 3.1 月历

- 视觉参考 Apple 日历的清楚网格和克制层级，不复制其品牌外观。
- 默认选中今天，支持切换月份和回到今天。
- 本地展示中国法定节假日与调休、农历节日和二十四节气；首发不接外部日历。
- 数据需标明覆盖年份，法定调休通过版本化数据更新。
- 有未完成任务的日期显示蓝色圆点和数量；只有已完成任务时显示淡化圆点。
- 已排程任务按执行日归属；未排程但有截止日期的任务按截止日归属；无日期任务不进入月历。

### 3.2 选中日期详情

- 默认今天时标题为“今日安排”，选择其他日期后同步切换。
- 展示节日/节气、固定日程、当天排程、当天截止任务和完成状态。
- 提供“新建任务”“新建日程”“安排当天”。
- 新建任务打开手动草案并预填日期；新建日程创建固定日程；安排当天唤起 AI 助手并绑定目标日期。

### 3.3 月历与日计划

- 今日页内部提供“月历 / 日计划”两个子视图。
- 月历是默认视图；早间计划通知和“安排当天”可进入日计划。
- 日计划展示固定日程、可编辑排程草案、已确认执行块和未排入任务原因。

## 4. 应用内 AI 助手

### 4.1 浮动形态

- 宠物图标固定在应用窗口右下角，不做 Windows 桌面级独立窗口，不支持拖动或缩放。
- 浮窗从图标上方展开，默认一直保持，只有用户主动收起。
- 切换页面不关闭浮窗，也不丢失当前对话。
- 图标状态：空闲静态、分析中轻微呼吸、待回答橙点、草案就绪蓝点及数量、失败红点；不随机移动或主动弹窗。

### 4.2 对话

- 支持多对话、新建、切换、搜索、自动命名、手动重命名、归档、恢复和永久删除。
- 切换器按“今天 / 更早”分组；归档只隐藏且可恢复，永久删除独立确认。
- 对话与消息一直保存在本地，除非用户永久删除。
- 归档对话不影响关联草案；切换对话不会自动跳页，存在草案时提供“查看草案”。
- 输入仅支持文字，不支持附件、图片、语音或引用控件。

### 4.3 快捷操作与路由

浮窗首版保留三个快捷操作：

- **创建任务**、**调整任务**：结构化结果进入任务页“草案”。
- **安排计划**：结果进入今日页目标日期的“日计划”。浮窗直接使用时默认今天，从月历进入时使用选中日期。

不提供“查询日程”快捷操作。

### 4.4 流式、锁定与停止

- 对话文字可流式显示，但结构化草案只有完整返回并通过本地校验后才一次更新。
- AI 分析期间只锁定本次涉及的草案、目标任务或目标日期计划，其他数据仍可操作。
- 用户尝试修改被锁对象时显示 Toast，说明先停止分析。
- 浮窗右下角在分析时显示暂停样式按钮，其操作语义为“停止分析”。
- 停止后保留部分文字并标记“已停止生成”，不生成或更新草案；迟到结果永久作废，不能断点续传。

## 5. 对话与表单同步

- AI 浮窗回答可以单向更新关联任务草案表单。
- 用户直接修改表单时，不向对话追加消息或状态。
- 手动修改字段优先级最高；AI 内部读取最新草案版本，但默认不能覆盖手动字段。
- AI 若需再次修改手动字段，必须由用户在对话中明确要求并确认新值。

## 6. 任务草案与任务页

### 6.1 统一草案

- 手动创建和 AI 创建都先产生持久化草案，共用同一增强表单。
- 草案停止输入约 500ms 后自动保存；自动保存不等于创建任务。
- 任务页新增“草案”筛选并显示数量，AI 分析完成后自动进入该筛选。
- 一次对话可以产生多条草案，用户逐条确认或放弃；不提供“全部创建”。
- 新建与修改都进入草案入口。修改草案展示现有值与建议值差异。

### 6.2 来源和字段状态

- 正式任务来源只有 `AI 生成`（`ai_assistant`）和 `手动创建`（`manual`）。
- 后续 AI 修改不会改变首次来源；变更历史记录修改来源为 AI 建议并经用户确认。
- 草案字段可显示“来自描述”“AI 整理”“需确认”“手动修改”；正式创建后收起字段级来源。

### 6.3 确认与 Inbox

- 只有标题是任务创建必填项；无效或矛盾数据必须阻止确认。
- 无日期草案确认按钮使用“确认并放入 Inbox”，确认后成为真实 Inbox 任务。
- 有日期草案确认后进入待办，但不会自动占用日历时间。
- 每条草案独立确认，确认令牌幂等，成功后从草案列表移除并刷新 SQLite 状态。
- 创建、修改和排程确认后提供 10 秒撤销；撤销也必须是事务并保留历史。

## 7. 日期、重复与长期任务

### 7.1 日期精度

- 截止日期和具体时刻分离；“下周五”保存日期，时刻为空，不补成 18:00 或 23:59。
- 日期是约束，不是执行时段；只有确认的执行块占用日历。
- “10 天”若可能表示总工作量或自然日期限，AI 必须追问，分别写入工作量与截止日期。

### 7.2 重复任务

- 支持每天、工作日、每周指定星期、每月指定日期，以及可选结束日期。
- 每次重复生成独立任务实例。
- 修改范围只提供“仅修改本次”和“修改本次及以后”；已完成历史永不改写。

### 7.3 长期任务

- 任务记录总工作量、累计实际耗时和可重新估算的剩余工作量。
- 工作量内部统一为分钟，界面允许分钟、小时或工作日；工作日换算来自工作时间设置。
- 完成当天执行块不等于完成整个任务；长期任务继续进入后续计划候选。
- 剩余量为零时只提示是否完成，只有用户明确确认才改变任务状态。
- 修改截止日期后，后续排程按新期限重新计算，但历史不被覆盖。

## 8. 每日闭环

### 8.1 早间计划

- 到设置时间发送 Windows 通知；若错过，进入应用时继续显示“今日计划尚未生成”。
- 通知和提醒本身不调用 AI；只有用户点击“生成今日计划”才调用模型。
- 不补生成过去日期的计划；同一天失败后由用户主动重试。
- 若昨日复盘未完成，必须先处理待复盘任务，再生成今日计划草案。
- Inbox 只提示整理，不直接排入时间线；转为待办后才成为排程候选。
- 日计划草案确认前不写计划块，确认后才通过事务提交。

### 8.2 晚间复盘

- 到设置时间只发送 Windows 通知，不强制打开应用页面。
- 复盘使用固定表单，不依赖 AI 对话。
- 每项记录完成、部分完成、未开始、取消或阻塞，以及实际耗时、可选延期原因和备注。
- 执行块默认带入计划时长作为实际耗时，用户可以修改。
- 用户可以重新估算剩余工作量，旧值和新值留痕。
- 未复盘任务进入“待复盘”，次日不得自动假定完成或延期。

## 9. AI 配置、数据与失败

- 用户在设置中配置 OpenAI API 兼容或 Responses API 兼容的 Base URL、模型名和 API Key。
- API Key 按用户决定以明文存入 SQLite；设置页掩码显示，日志、审计、导出和诊断不得包含 Key，并明确数据库文件泄露风险。
- 每次只发送当前操作必要的最小上下文，不发送其他对话、完整任务库或已归档内容。
- AI 或网络故障不影响月历、任务、草案、复盘和手动操作；错误显示原因与重试。
- 当前对话和草案在失败后保留，不允许半成品结构化结果写入。

## 10. 并发、通知和持久化不变量

- 每次 AI 分析绑定 `run_id`、`conversation_id`、目标对象和版本；停止或过期运行的结果不可应用。
- 草案和计划使用版本检查，防止旧结果覆盖新数据。
- 确认操作必须幂等，重复点击或超时重试不得重复创建。
- 每日通知按类型和日期去重，休眠、解锁或重复启动只补发一次提醒状态。
- 对话和消息分页加载并支持本地全文搜索；无自动删除策略。
- 所有成功反馈只来自事务提交后重新读取的 SQLite 状态。

## 11. 首发明确不做

- 外部日历同步、账号、云同步、网页搜索、附件、图片、语音和本地模型。
- Windows 桌面级悬浮宠物、自由拖动或缩放 AI 浮窗。
- AI 自动调用、自动确认任务、自动写入排程、自动判定任务完成。
- 批量“全部创建”任务草案。
- 复杂重复规则、项目/目标/子任务层级。

## 12. 推荐实施顺序

1. 数据迁移与领域状态：对话、消息、草案、来源、日期精度、重复实例、长期工作量、执行块与复盘。
2. Rust 事务与确定性测试：幂等确认、运行失效、版本冲突、撤销和最终 SQLite 状态。
3. 任务页草案入口与统一表单。
4. 今日页月历、选中日期详情和日计划子视图。
5. 应用内 AI 宠物、对话切换、流式与停止。
6. 模型连接、Windows 通知、早间提醒和晚间复盘。
7. 视觉、无障碍、响应式、迁移恢复和完整验收。

## 13. 冻结后的变更规则

- 后续任务开始前先读取本文件、`CONTEXT.md` 和相关 ADR，再以实施规格定位迁移步骤。
- 现有代码保留旧首页、旧导航或合并时间戳字段，只代表待迁移现状，不能作为继续扩展旧方案的依据。
- 若新需求改变已冻结边界，必须先获得用户明确确认，并在本文件记录变更日期、原因和被替代条目；不能只改界面或单份说明。
- 产品边界变化后，同一任务内同步术语、产品说明、设计规范、实施规格、README、相关 ADR 和验收项；未完成同步时不得称为新基线。
- ADR 只记录难以逆转、脱离背景会令人困惑且确有取舍的决定；普通样式和易改交互直接维护本基线与设计规范。
